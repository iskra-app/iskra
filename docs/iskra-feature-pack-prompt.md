# Промпт для Claude Code: дополнительные фичи поверх MVP (Iskra)

Скопируй всё, что ниже, и вставь в Claude Code.

---

Добавь в проект Iskra (Matrix-клиент на SwiftUI + matrix-rust-sdk) набор фич поверх уже реализованного MVP. Где уместно — сверяйся с архитектурой **element-x-ios** (github.com/element-hq/element-x-ios) как с референсом, особенно там, где фича завязана на Matrix-протокол (spaces, редактирование/удаление, реакции, threading). Помни про AGPL-3.0 лицензию element-x-ios — используй как учебный референс, не копируй код дословно; если где-то заимствуешь напрямую — явно пометь это.

Можешь запускать субагентов для параллельной работы по независимым блокам фич — раздели зоны так, чтобы не было конфликтов правок в одних и тех же файлах.

## Сообщения и переписка

- **Индикатор «печатает…»** — по дизайну и таймингам ориентируйся на iMessage (плавное появление/исчезание, три точки анимацией, не резкий поп-ап).
- **Упоминания (@юзер)** — с визуальной подсветкой в тексте сообщения и отдельной обработкой в пуш-уведомлениях/списке чатов (упоминания должны быть заметны отдельно от обычных сообщений).
- **Тап по ссылкам** — ссылки в сообщениях кликабельны, но перед открытием в браузере показывай подтверждение с полным адресом ссылки (чтобы пользователь видел, куда реально ведёт ссылка, а не текст-маскировку) и явную кнопку «открыть» / «отмена».
- **Пересылка сообщений** между чатами (включая медиа-вложения).
- **Локальные черновики** — недописанный текст в поле ввода сохраняется при уходе из чата и восстанавливается при возврате, per-комната.
- **Поиск по одному чату** — локальный поиск внутри открытой комнаты (отдельно от уже реализованного глобального поиска).

## Комнаты и организация

- **Spaces** — в интерфейсе и во всех UI-текстах называй их **«пространства»** (не «спейсы», не «спейс» — пользователю должно быть понятно без матрикс-жаргона). Логика группировки — аналогично element-x-ios (сверься с их реализацией иерархии spaces/rooms), но отображение своё:
  - в общем списке чатов пространство выглядит как обычная строка чата, никакой отдельной секции/вкладки
  - аватарка пространства — **квадратная со скруглёнными углами** (в отличие от круглых аватарок обычных чатов — так пространство визуально отличимо с первого взгляда)
  - в превью строки — название пространства, и в качестве «последнего сообщения» показывается последнее сообщение из **последней активной комнаты** этого пространства (то есть предпросмотр ведёт себя как у самого активного чата внутри)
  - тап по строке пространства открывает отдельный экран со списком всех комнат этого пространства (не открывает сразу чат)
- **Закрепление чатов** — закреплённые комнаты вверху списка, с возможностью изменить порядок. **Жёсткий лимит — максимум 5 закреплённых чатов одновременно.** Если пользователь пытается закрепить 6-й — не давай закрепить молча, покажи понятное сообщение (например, предложи сначала открепить один из существующих) вместо того, чтобы просто вытеснять самый старый закреп без объяснения.
- **Архив** — архивирование неактивных комнат без выхода из них и без потери истории; архивные чаты не засоряют основной список, но легко доступны отдельным экраном.

## Свайпы на списке чатов

На главном экране (список чатов) реализуй свайп-действия по строке чата, в духе стандартных iOS-паттернов (как в Mail/Messages):

- **Свайп вправо** — открывает действия: **«отметить прочитанным»** и **«закрепить»** (закрепить — с учётом лимита в 5 чатов из пункта выше).
- **Свайп влево** — открывает действия: **«архивировать»** и **«удалить»**.

Учти обычные детали UX свайпов: иконка + подпись на каждом действии, разный цвет фона под каждое действие (стандартная нативная палитра, не выдумывай свою), возможность полного свайпа для действия по умолчанию (первое в списке), поддержка для VoiceOver — свайп-действия должны быть доступны и через accessibility actions, а не только жестом.

Для пространств в этом же списке свайпы должны работать логично: «закрепить»/«архивировать» применяются к пространству целиком, а не к его комнатам по отдельности.

## Свайп-ответ на сообщения (внутри чата)

Внутри переписки добавь свайп по пузырю сообщения для быстрого ответа (reply), в духе iMessage/Telegram:

- **На своих сообщениях** (справа, отправленных тобой) — свайп **влево** инициирует ответ на это сообщение.
- **На чужих сообщениях** (слева, от собеседника) — свайп **вправо** инициирует ответ на это сообщение.

То есть направление свайпа всегда «к центру/от края экрана», независимо от того, чьё это сообщение — это привычный паттерн, не заставляй пользователя думать в какую сторону тянуть.

Детали реализации:
- свайп не должен быть полным (в отличие от свайпов на списке чатов) — это короткий, пружинящий жест: потянул до порога → сработала haptic-отдача → сообщение цитируется в поле ввода как reply, свайп не «улетает» и не требует довести до конца экрана
- жест не должен конфликтовать с системным свайпом «назад» (edge swipe) на сообщениях от собеседника, если чат открыт как push-экран — проверь на реальном устройстве, что зона жеста не перехватывает системную навигацию у самого края экрана
- добавь такое же действие «ответить» в контекстное меню по long-press на сообщении — свайп должен быть быстрым способом, а не единственным

## Безопасность и модерация

- **Блокировка приложения** по биометрии (Face ID/Touch ID) и/или пинкоду при открытии/возврате из фона. Настраиваемый таймаут (сразу / через N минут неактивности).
- **Скрытие превью в системных пушах и в списке чатов**, пока приложение заблокировано: показывай общее «новое сообщение» без содержимого и без имени отправителя, если пользователь включил эту опцию (или это часть той же настройки блокировки — реши по UX, но сделай явной и понятной).
- **Блокировка пользователей** — заблокированный больше не может писать/звонить, его сообщения скрываются.
- **Репорт спама/абьюза** — стандартный Matrix-механизм репорта контента модераторам/на homeserver, с простой формой причины.

## Медиа

- **Галерея вложений по комнате** — отдельный экран со всеми медиа/файлами конкретной комнаты (сетка для фото/видео, список для файлов), без пролистывания всей истории сообщений.
- **Просмотрщик фото и видео** — полноэкранный, с горизонтальным перелистыванием между вложениями в духе Telegram (свайп между медиа внутри одной комнаты/подборки, поддержка пинч-зума для фото, стандартные контролы воспроизведения для видео).

## Системная интеграция Apple

- **Share Extension** — возможность шарить контент (текст, ссылки, фото, видео, файлы) из других приложений напрямую в конкретный чат Iskra через системное меню «Поделиться».
- **App Intents** — базовый набор интентов для Siri/Shortcuts/Spotlight: отправить сообщение в конкретный чат, открыть чат, возможно — быстрый ответ на последнее сообщение. Сделай интенты типизированными (через параметры с сущностями чатов), не просто «открыть приложение».

## Общие требования по всему пакету

- Everything above should follow the same principles already set for the project: Apple HIG-совместимый нативный UI, минимализм, Liquid Glass где уместно, дружелюбные UI-тексты без жаргона.
- Все новые точки, где данные могут утечь (share extension, app intents, скрытие превью) — проверяй с той же строгостью по приватности, что и остальной проект: никаких логов с содержимым, секреты только в Keychain/App Group Keychain при обмене между расширением и основным приложением.
- Пиши тесты на новую логику там, где она нетривиальна (поиск, состояние черновиков, блокировка/разблокировка по таймауту).

## Формат сдачи

Резюме в чат по каждому крупному блоку (сообщения / комнаты / безопасность / медиа / apple-интеграция): что реализовано, какие файлы/модули основные, что стоит протестировать вручную. Если что-то из фичи невозможно реализовать чисто (без костылей) в рамках Matrix-протокола или API Apple — скажи прямо, не делай тихих компромиссов.
