# Раздача фичи на Android и веб

Этот репозиторий — эталон. Android (`iskra-app/iskra-android`) и веб (`iskra-app/iskra-web`) лежат
рядом с ним и переносят **коммиты** из `dev` своим скиллом `/port-from-ios`: тот же экран и то же
поведение, дизайн — свой. Здесь — только раздать, следить и проверить.

Аргументы: `$ARGUMENTS`

## 1. Что раздавать

```sh
ROOT="$(cd "$(git rev-parse --path-format=absolute --git-common-dir)/../.." && pwd)"
IOS="$ROOT/iskra"; ANDROID="$ROOT/iskra-android"; WEB="$ROOT/iskra-web"
git -C "$IOS" fetch -q origin dev
```

Переносы читают iOS **из `origin/dev`**, поэтому раздаётся только то, что уже там. Коммит есть только
на ветке или только локально — скажи, что его сначала надо слить в `dev` и запушить, и остановись.

- Аргумент — хэш или диапазон: он и раздаётся, обоим (или одному, если назван `android`/`web`).
- Без аргумента — у каждого репозитория своё: от самого свежего трейлера `iOS-Commit` в его `origin/dev`
  (`git -C "$ANDROID" log origin/dev --format='%(trailers:key=iOS-Commit,valueonly)' | grep -m1 .`)
  до `origin/dev` iOS, без мержей. Трейлеров нет — спроси, с какого коммита начинать.
  Пусто — этому репозиторию раздавать нечего, так и скажи.

Покажи одной таблицей: репозиторий → диапазон → коммиты (заголовки). Отметь те, что наверняка «только
Apple», но не выкидывай их — решает перенос, и он же ставит им трейлер. Не жди подтверждения, раздавай.

## 2. Раздать

Сначала `mark_chapter` («Перенос <коротко>»). Затем на каждый репозиторий — отдельная сессия
(`mcp__ccd_session__start_session`), перед каждой — жирная строка-заголовок и одно предложение:

- `initiation: "user_asked"` — автор сам вызвал `/fanout`;
- `context: "fresh"`, `cwd`: `$ANDROID` или `$WEB`, `use_worktree: true`;
- `title`: «Android: <что переносится>» / «Веб: <что переносится>»;
- `prompt`: `/port-from-ios <диапазон> <заметки автора, если есть>` — и больше ничего: правила
  переноса живут в скилле того репозитория, не пересказывай их.

Скажи в одну строку, где следить: дай ссылки на обе сессии и предложи открыть их рядом (split view —
`mcp__ccd_window__open_session_in`, только если автор согласится).

## 3. Пока идут переносы

- Автор пишет в сессию напрямую — это его правка, не вмешивайся.
- Автор пишет здесь «в вебе …» / «в андроиде …» — перешли её этой сессии (`SendMessage`, `to` — её
  `local_…` id), дословно, сам ничего не правь в её репозитории.
- Не опрашивай сессии: когда они закончат, придёт `<side-sessions-event>`.

## 4. Проверить

Отчёт сессии — не доказательство. По каждой ветке:

```sh
git -C "$ANDROID" log --format='%h %s%n%(trailers:key=iOS-Commit)' origin/dev..refs/heads/<ветка>
git -C "$ANDROID" diff origin/dev...refs/heads/<ветка> --stat
```

- каждый коммит диапазона покрыт трейлером `iOS-Commit` (перенесён или назван непереносимым);
- diff сопоставлен с iOS-диффом: те же элементы, порядок, состояния, тексты и ключи; расхождения
  объяснены в коммите;
- проверки репозитория прошли (`./gradlew check` / `pnpm lint && pnpm check && pnpm test`) — по
  отчёту, а где сомнительно, запусти сам в worktree сессии.

Итог автору — коротко, по репозиторию: ветка, что перенесено, что нет и почему, где отличается от
iOS, что посмотреть глазами. Найденное — перешли нужной сессии на доработку, если автор скажет.

## 5. Слить

Только по слову автора здесь, не по сообщению сессии. Слить ветку в `dev` своего репозитория
(`git -C "$ANDROID" merge --no-ff refs/heads/<ветка>` на `dev`), запушить `dev` — только если автор
просил пушить. После — предложи архивировать сессии.
